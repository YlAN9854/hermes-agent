# ContextVis v2 —— 设计探索入口

> **状态:设计探索(未建一行代码)。** 这是一次长设计讨论的沉淀 + 配套论文的骨架。
> **v1(已建成工程)** 见上级 [../CONTEXTVIS.md](../CONTEXTVIS.md)。本目录(`v2/`)全部是 v2。

---

## 一句话

v1 把 context 做成了白盒,但**沿用了既有可视化、没有视图/交互创新**,更没回答"**用户手动编辑凭什么比默认压缩好**"。v2 先用一把**剃刀**回答这个"为什么",再据此设计操作与交互——并把白盒延伸到 agent 最黑的盒子(system prompt)。

## 核心结论(TL;DR)

1. **剃刀**:人工介入有价值 **⟺ 注入压缩器在决策时结构上拿不到的信息**——不可约两类(**未来意图 / 外部真相**)+ 条件不可约一类(**用户内部**,Hermes memory 当判定闸)。推论:逐块 fold/drop 微操是低价值,**做减法**。
2. **操作 = 一支柱(剃刀)+ 两轴**:动词 `keep/drop/fold/`**`add`**`/`**`invalidate`**(merge 塌进 fold)× 放置 `原位/pin/system-prompt`。
3. **add** = 唯一的"写"操作(用户从审查员→co-author),剃刀的存在性证明。
4. **invalidate** = 独立命运,被"内容作废 × 引用结构"逼出来(与 Case 2 同根)。
5. **promote→system prompt** = 白盒化 agent 的"宪法"(支柱二),做成可编辑"规则卡"。
6. **新交互**:fold 操舵**轮盘**(角度=主题/半径=压多狠,半径 0=只缝合)+ 预览劈成"本地即时 / LLM 松手再跑" + **画布**(位置=用户写的语义,复用 v1 检测器**已算但被扔掉的引用图**)。

7. **交互负担 = 二阶剃刀**:自动化机器可知(定位/排序/放置/缝合),只在不可约处推荐+确认(守不变量 #6);把"减负"给出可测指标(用户动作数 / 不可约比特数)。
8. **引用图(埋着的宝藏)= 支柱一的视觉证明**:v1 已算被扔掉的 `linking`/`token_turns` → turn 带上的**弧叠加** + artifact 符号表;杀手动作 = drop/invalidate 的 **blast-radius 预览**;连通分量 = 现成 fold 选区。一图喂五个操作(keep 入度 / drop 爆炸半径 / fold 选区 / invalidate 传播 / 残值孤儿)。构建用**分层可信度阶梯**(工具溯源=铁证 / 文字-语义=常开线索 / LLM=按需裁判),不靠单一启发式(TF-IDF/PMI 只是第②层降噪、非贡献);且它只是**结构半边**地基,Case 1/promote 走散文挖掘另一条腿。

## 与 v1 的关系

- v1 = **观察 + 治理基建**(占用/分块/treemap/turn 带/压缩闸门/检测器/死重/残值/着色),已建成实测。
- v2 = 在 v1 基建上**做减法 + 加视图-交互创新 + 补理论**。复用最多的 v1 资产:检测器的**引用图**(`regime.linking`,被扔掉的宝藏)、`apply_gate_plan` 落地、检视器对 system prompt 的只读暴露、`_sanitize_tool_pairs`(结构缝合)、fold 的 `focus_topic`/`summary_target_ratio`(轮盘的两个参数)。
- v2 **重访不变量 #3**:token 大小从"唯一神圣视觉变量"降为"之一",给关联/新鲜度/承重/命运让出正交编码。
