## 1. 两根轴(整体形状)

v2 收紧后,整套操作 = **一根理论支柱(剃刀)+ 两根实用轴**:

- **动词轴**:`keep` · `drop` · `fold` · **`add`** · **`invalidate`**(新增加粗两个;**merge 不立为动词**——它=fold+用户侧重)。
- **放置/耐久轴**:`原位(inline)` · `钉死 context(pin)` · **`system-prompt`**(三档耐久度,Hermes 现成有)。

任一操作 = 动词 × 放置。摇杆(steered fold)是 fold 的精装,不另立。

## 2. 动词逐个(含剃刀证成 + 必要性 case)

### add —— 整套里唯一的"写"操作(最强展品)
keep/drop/fold/invalidate 都在治理"**机器写的内容**"(用户=审查员);**add 是用户自己往 context 写**(用户=**co-author**)。这是身份的跃迁,也是论文里**剃刀的存在性证明**(最干净地坐实"人注入了机器没有的信息")。

- **是什么**:注入"忘了说的约束 / 临时纠正 / 指向",但**不值得单开一轮 turn**。
- **与 turn 的本质区别(=必要性)**:turn 是**对话动作**(触发生成、agent 必须回应、占整轮、下次又变旧被压);add 是**非对话注入**(随行注解,看得见但不必回应;配钉死区穿越压缩永久承重)。今天你只能开一轮 → add 严格更优。
- **剃刀**:注入外部真相 + 意图,机器结构上拿不到。强通过。

### invalidate —— 独立命运(被"作废 × 引用结构"逼出来)
- **是什么**:标某块"**不再成立**",agent 别再据它行动、压缩器可降权——但**与 drop 不同,块留着当历史**。
- **与 drop 的关键区别**:drop 连"曾经这么以为"都抹掉 → agent 可能**重蹈覆辙**;invalidate 留住"我们已排除过 X / 这条曾真但变了"。
- **必要性尺子(防止塌进 fold/add)**:
  > invalidate 必要 **当且仅当 (内容已假) ∧ (drop 会砸引用 ∨ "曾真/曾试"本身有用)**。两者皆无 → drop 就够。
- **最强 case(砸不塌)**:turn 3 记下 `DB_URL=old`,turn 5–15 据它写了代码(全引用),turn 20 你迁库 `URL=new`。keep→用假值;drop→下游引用悬空(爆炸半径=Case 2);**只有 invalidate 同时满足"别用假值"+"别砸下游"**。
- **会塌的 case(别用来论证)**:死路("别再试库 X")、撤回指令——这些 = fold + 一句负面 verdict(那 verdict 其实是 add)。
- **论文价值**:invalidate **不是凭空第 5 个动词,是被"内容作废 × 引用结构"逼出来的**(没引用图你只会 drop;有了引用图 drop 有爆炸半径,才需"留着但剥夺权威")。它与 Case 2 **同根**;也是 v1 残值"被取代旧读"信号的**人工版**(机器靠"又读一次"判废,人不用再读就知道)。

### keep / fold / drop —— v1 已建,微操层(低价值,见剃刀推论)
保留,但**不是 v2 的重点**;v2 的能量在 add / invalidate / 放置 / 操舵。

## 3. 放置/耐久轴 + promote(支柱二:白盒化 system prompt)

放置不是新价值类——"这条重要、放耐久处" = 外部真相(重要性)× 一个放置选择。但它**低负担、客观、有 Hermes 现成机制**,值得做成可见档位。

耐久度梯度:`volatile-context < history < pin < system-prompt`。

### promote → system prompt
- **定位**:= `(add 或 move) × 放置=system-prompt` + 一步**蒸馏**。不破坏"动词 5 个",是**放置轴顶档被点亮**。
- **pin vs promote**:pin 保**在场**(presence);promote 给**权威**(authority,进 system prompt → 置顶、不被压、当**规则**看)。
- **必要性 case**:约束 pin 着、agent 仍违反(作为 history 被近因偏置淹没,权重干不过近期 context)→ **在场 ≠ 被遵守** → promote 才解决。剃刀:"这是**规则**不是随口一说"=权威状态,机器看不出。
- **payoff(论文亮点 = 支柱二)**:**白盒化 agent 最黑的盒子——system prompt**。使命从"白盒化对话历史"**延伸到 agent 的'宪法'**。Hermes system prompt 本就分 `stable/context/volatile` 三节(`build_system_prompt_parts`),v1 检视器**已只读露出**;promote = **把它变成可写**。基建已就位。

## 4. 新交互

> **形态序（引用图相关）**：第一形态是 §6 的**弧叠加**（叠在 turn 带上、保留时间脊柱、能 ship，**已建成**）；§4c 的画布是展开形态——现已落地为常驻右侧 `TurnCanvas`（**每 turn 内类型版小 treemap + 弧落子格 + 产物/关键词追踪**，见 §6 实现状态），但仍是"沿时间脊柱排"的受控画布，非自由 2D 重排（后者 = 野心形态，留后）。引用图的数据来源/性质/治理动作统一收在 §6。

### 4a. 摇杆(轮盘)—— 给 fold 一个连续可探索的舵
输入框弱在:得知道输啥、只能给一个串、给完看不见效果。摇杆破这三点,**关键是想清方向代表什么**:

- **极点 = 这次选中内容里实际存在的主题**(检测器逐块 topic / 抽取关键词自动生成,标在盘边)→ 用户不用知道选项,**盘把选项显示给你**。
- **二自由度**:**角度 = 偏向哪个子主题**(→`focus_topic`,可加权);**半径 = 压多狠**(圆心=轻压近逐字 → 边缘=狠压成一句 gist,→`summary_target_ratio`)。**不是新机器,是给老 fold 参数一个连续、可见的手柄。**
- **半径最弱边界(用户洞见)= 润色/缝合、零压缩**:半径轴是一条谱,边缘=hard gist,**圆心=零压缩、只缝合**。于是 **add 与 fold 是同一台机器的两端**(都"从输入产出一块连贯 chunk",半径=压多狠)。结构缝合 v1 已有(`_sanitize_tool_pairs` 修工具对);半径 0 是它的**语义版**(连贯修复)。
  - **张力**:无缝缝合会**抹掉作者身份**;一条钉死约束通常**该显式署名**(`[用户注入]`),否则=静默改 context(违反不变量 #6)。→ 对 add:**结构合法 + 位置=必须;语义揉合=可选**。位置问题大半自消(add→pin 是全局 note、位置无关;只有内联历史插入才需位置+缝合)。

- **预览 vs LLM 延迟(mentor 建议 + 约束)**:**别实时生成摘要文本**(卡在 provider/网速)。**劈两层**:拖动中=**即时本地零 LLM**(① 各主题 token 预算分配条实时变 ② 抽取式 BM25 高亮"大概会强调这些行");**松手=才跑一次 LLM** 生成真摘要。预览的是**结构**(什么留、预算怎么分),比"被慢模型牵着"更诚实。

### 4b. promote 的交互:把 system prompt 做成"规则卡"面板
- **手势:往上拖过钉死区**,进独立的"**standing rules / 宪法**"区(在所有 context 之上)→ 耐久度成一条**竖直梯度**,拖得越高越权威。
- **promote 触发蒸馏**:冗长块进不了 system prompt → 系统提"提取出的规则:[可编辑]",用户改/确认 → **你 authored 了这条规则**;原块随后可 fold/drop。
- **promoted = 规则卡**:可编辑、可开关、可 **demote**(过期摘掉,防积垢)→ 生命周期闭环(demote = 对规则卡的 invalidate)。
- **(可选,后做)违反计**:检测器扫后续轮标"被违反 N 次",既为 promote 自动建议(像死重/残值)、又让你看规则上岗后生效。**需 LLM 判违反,不稳,先挂着。**
- **⚠ 待解**:此处"竖直=权威"与 turn 带"竖直=时间"**轴冲突**,需在设计里调和。

### 4c. 画布方向(mentor 建议)—— 位置从"系统给"翻成"用户写"
treemap 里位置=系统按大小打包;**画布里位置=用户写的语义**。这一翻转正是"注入私有信息"的底座。

- **重力带 = 命运,无菜单**:顶=钉死/system、中=活区(working set=焦点)、底=褪色(狠压)。**拖进哪条带=那个动作**。默认位置由检测器给(主线→活区、已完成支线→底),**用户只挪机器猜错的几个** → effort 正比于"机器不知道的量"(对齐剃刀)。
- **拖一簇到活区 = 重指向焦点 = 声明未来意图**(把那个不可约的"我要 pivot"变成一个拖拽)。
- **引用图是画布原生内容(埋着的宝藏)**:v1 启发式检测器**已经在算跨轮引用图**(`linking`=出现在 ≥2 turn 的 salient,`token_turns` 记哪个产物在哪些轮复现),却**只用于 task/forest 二元判断后扔掉**。画布上它=边;连通分量=一条支线;拎起大块→拴着的下游一起亮(**Case 2 爆炸半径,字面发生**)。treemap 画不了边,画布天生为此。
- **诚实的坑**:① 手排 N 块 = 比 treemap 更累 → **必须自动布局**(按引用图力导向),用户只微调;② >~80 块成毛球 → 收粒度到簇(轮/主题/组件);③ 必须**驱动真实压缩行为**,否则是装饰(违反"白盒优先于美观")。

## 5. 交互负担 = 二阶剃刀（自动机器可知、只问不可约）

剃刀（[principle.md](principle.md) §2）一阶回答"哪些操作有价值"。把同一把刀**用在交互设计上**得到二阶版：

> **每个操作 = 机器可知的脚手架 + 机器不可知的增量。自动化前者，只在后者上"推荐 + 确认"，永不静默应用（守 [../../CLAUDE.md](../../CLAUDE.md) 不变量 #6）。**

安全栏：机器可知的活（定位/排序/预填/放置/缝合/找引用）可以自动；**机器不可知的判定（这是不是规则？这条是否已假？add 什么？）只能推荐候选 + 用户确认，绝不替用户跨过这条线**——跨过去 = 机器替你猜权威/真假 = 既破剃刀也破 #6。

### 逐 verb 的"机器可知 / 不可约"切分

| verb | 机器可知（系统自动） | 不可约（只问用户） | 自动度 |
|---|---|---|---|
| **keep** | 承重度 = 引用图**入度**（被多轮引用），见 §6 | 基本无，或一键确认 | 高，可直接推荐 |
| **promote** | **候选挖掘**：扫用户 authored 轮里的 deontic+泛化语言（"必须/永远/从现在起/别再"） | 这条**现在还算数吗** = 权威 + 时效（未来意图） | 推荐候选，必须确认 |
| **fold/drop** | done-支线 triage（v1 检测器） | ~无（机器可知，故低价值，故全自动） | 全自动（见下） |
| **add** | **放置**（相似度 + 引用图）、**缝合**（半径 0 fold）、**矛盾检测** | **内容**（用户自己写，存在性证明） | 内容必手写，周边全自动 |
| **invalidate** | **定位**（语义搜索 / add 隐含）、**爆炸半径**（引用图下游） | **"这条已假"** = 外部真相 | 定位自动，判定必问 |

### 由此浮现的设计点

- **fold/drop 检测器的诚实定位**：按剃刀它**不是贡献**（主线/支线判定是机器可知的 → 人工介入不增值）。它的身份是**减负器 + 使能器**——清掉机器可知的噪声，让稀缺的人类注意力集中到不可约的 add/invalidate/promote；且其副产物**引用图**（§6）是 Case 2 / keep 推荐 / invalidate 必要性的共同地基。**别把检测器包装成新颖贡献；头条留给 add/invalidate/promote + 剃刀。**
- **promote 候选挖掘 = Case 1 的可操作版**：被埋掉的早期约束（Py3.8）本就写在早期用户轮里 → 扫用户轮的 deontic+泛化语言把它捞出来："你 30 轮前说过、这是条标准 —— 提升进 system prompt？"
- **add 是 invalidate 的天然入口（交叉点）**：用户 add 一条纠正（"DB_URL 现在是 X"），系统按**实体重叠**（同一个 `DB_URL` token）检测到它矛盾于旧块 → 顺手提"把那条旧的判作废？"。一条流同时解决"add 放哪"（§2 add 放置）和"invalidate 怎么找到目标"（§2 invalidate 定位）。

### 论文价值：把"减负"升格成评估方法

二阶剃刀给出一个可测指标：

> **效率 = 用户动作数 / 注入的不可约比特数。** 好的 ContextVis 把它压向 1——每个用户动作都携带机器不可知的载荷，零动作浪费在机器本可代劳的记账（翻找/排序/定位/缝合）上。

对照实验骨架：**纯 transcript 手编（用户自己 locate+rank+place+stitch+decide，大量机器可知杂活）vs ContextVis（机器包办机器可知、用户只做不可约）**；机器可知动作的减少量 = 可量化的贡献。一阶剃刀说"价值在哪"，这个指标量"UI 有没有把力气都集中在那里"。

### 为什么是"正确的原语"

位置式压缩的根本错误 = **拿"位置"当"结构/相关性"的代理**（折中段只因"旧 = 可折"）。

> **引用图就是位置在盲目近似的那个真实结构本身。**

一个中段轮若是**枢纽**（被尾部多轮引用），位置说"折"、结构说"承重、别动"。**引用图恰恰暴露"位置 ≠ 结构"在哪**——它与主线/支线检测同源，但是更底层、更丰富的形态。可视化它 = 把 paper 中心论点变成肉眼可见，也是 [principle.md](principle.md) §1 许诺的"正交编码"的具体落地。

一图喂五个操作（这种收敛本身即 [../../CLAUDE.md](../../CLAUDE.md) #2 一个隐喻贯穿全局）：

| 引用图特征 | 喂给 |
|---|---|
| 高**入度** | keep / promote 推荐（承重） |
| **出边/下游** | drop 爆炸半径（Case 2） |
| **连通分量** | fold 的**目标选区**（见下） |
| **下游传递闭包** | invalidate 失效传播 |
| **零出度 + done** | 残值"孤儿"信号 |

### 怎么建：一把"可信度阶梯"（分层，不靠单一启发式）

单一词汇启发式（现 v1 的 `linking`/`token_turns`，`regime.py:329`）太脆——它只是"文字重叠"一种来源，还把"共现"误当"依赖"。改用**分层**：越上越可信、越窄越贵；底层常开画底图，顶层只在关键时刻点一次。

| 层 | 怎么判断 | 可信度 | 覆盖 | 成本 |
|---|---|---|---|---|
| **① 工具溯源（精度骨架）** | 第 5 轮 `write_file(X)` → 第 12 轮 `read_file(X)`：系统真干了、不是猜 | 铁证（真依赖 + 有向） | 窄（只走工具的：文件/命令） | ~免费（`regime.py:175-182` 已抽工具/文件名） |
| **② 文字/语义重叠（常开底图）** | 两轮"在说同一个东西"：共享词（v1 那套）或意思相近（嵌入向量，连换说法/代词都认） | 仅线索（相关 ≠ 依赖、无向） | 广 | 便宜 |
| **③ LLM 按需（高风险裁判）** | 直接问"第 12 轮真依赖第 3 轮吗" | 唯一给真·有向依赖 | 广 | 慢 + 花钱 + 可能错 |

**信任顺序 = 阶梯顺序**：工具溯源是地基，文字/语义是提示，LLM 是用户**正要 drop/invalidate 时**确认 blast-radius 的裁判（只在那一瞬付费）。

**第②层的降噪（是螺丝、不是单独一层）**：**TF-IDF**（词对某轮的辨识度：本轮多、别处少 = 重要 → 自动替掉手写停用词 `regime.py:40`）+ **PMI/lift**（共现是真关系还是巧合 → 边权用"共享词有多稀奇"而非"共享几个"）。⚠ 这俩是工程螺丝、**不是 method 贡献**（见 §5：构建层是 enabler 不是 headline）；**别上 Apriori 之类**徒增复杂度 + 立一个扛不住的弱 method claim。

### ⚠ 引用图是"结构半边"的地基，不是全部

引用图只能连**复现的 artifact**。一条**说一次就被遗忘**的散文约束（Case 1 的"必须兼容 Python 3.8"）：现抽取器纯小写普通词不收（`regime.py:130`）、入图又要跨 ≥2 轮（`regime.py:333`）→ **零 salient、永不入图**；而且"只提一次"的东西，共现图**结构上**就抓不到（再放宽抽取也没用）。

→ 分两条腿，别混（否则一个 Case 1 就戳穿"图 = 全文地基"）：

| 论文半边 | 靠 |
|---|---|
| Case 2 / invalidate / fold 选区 / drop 爆炸半径 / keep 入度 | **引用图**（本节，结构/依赖） |
| Case 1 / promote（被埋的散文约束） | **另一条腿**：用户轮规范性散文的**单次浮现**（TF-IDF 高 IDF 浮稀有重要词 + deontic/泛化语言，见 §5）——**不是引用图** |

### 第一形态：弧叠加在 turn 带上（不是另起画布）

**不**一上来上自由 2D 画布（毛球 + 手排 + 抛弃时间脊柱）。最强第一形态 = **在现有 turn 带上叠加弧线（arc diagram）**：

- turn 带本就是一列纵向线性排列的轮 → 侧沟画弧连共享 artifact 的轮 = **白嫖一张 arc diagram**，叠在脊柱上。
- 好处：**时间轴保留**（#5）、**大小高度保留**（#3 不背叛），把引用作为第二视觉通道加上 = 字面意义"**打破大小垄断却不换隐喻**"（#2）。比画布克制、可辩护、能 ship。

视觉词汇（沿用既有语言）：
- 选中某轮 T → **下游弧（T→后续）一色** = "谁依赖我" = 爆炸半径；**上游弧（前序→T）另一色** = "我依赖什么" = provenance。**Case 2 字面发生在屏幕上。**
- 弧**粗细 = 边权**（用共享词的稀奇度 / PMI，非单纯"共享几个"；见上「可信度阶梯」第②层），工具溯源的实线边（第①层）比文字线索更粗/更实。
- 加一条 **artifact 泳道**：列出复现的 artifact（文件/变量/决策）= 这段对话的**符号表 / dramatis personae**；悬停一个 artifact 点亮它碰过的所有轮。泳道本身即强白盒产物（"DB_URL：触及 turn 3,5,7,12；turn 20 判作废"）。**已建成（Stage 3，画布右窄条「产物/关键词索引列」）**：产物（`files`，文件路径按 token 量级）在前、关键词（`keywords`，salient token）在后；点一项 → 画布高亮其全部触及子格 + 贯穿路径（§6 实现状态）。

### 每个视觉挂一个动作（守 #7，不当装饰）

- 弧从某轮发散到很多后续轮 → 悬停"被 N 轮引用" → 一键 keep/pin/promote。
- 拖去 drop → N 条下游弧变红 → "drop 会砸 N 个下游" → **逼改用 fold 或 invalidate**。
- invalidate 它 → 下游弧转琥珀（suspect）→ "建立在已假前提上" → 失效传播可见。
- **连通分量 = 一条线索 = 现成 fold 选区**：不用手挑多块，一个分量 = 天然选择单元，点它 → 对整条线索摇杆 fold（§4a）。**引用图消化掉"多块选择负担"。**

### 与画布（§4c）的关系

§4c 的画布**已落地为常驻右侧 `TurnCanvas`**（每 turn 内类型版小 treemap、弧落子格、产物/关键词追踪、字号随量级），但仍**沿时间脊柱排**（受控画布）；**自由 2D 重排**（用户写语义位置、力导向布局）留作野心形态。**弧叠加 + 受控画布已证明 chunk 级粒度的价值。** 可独立成立的贡献候选：**"影响感知的 context 编辑（impact-aware editing）"**——每个破坏性操作提交前展示传递爆炸半径，把 #6（干预透明）**量化**。据目前所知，context 编辑领域少见"删除前显示 blast radius"。

## 7. 驱动 case(找 insight 的锚点)

- **Case 1 ·「被遗忘的约束」(承重 ≠ 大小)**:开局"必须兼容 Py3.8"占 20 token,40 轮后被压掉,agent 写 f-string。treemap 把它画成看不见的细丝——**大小编码主动误导**(越承重越画小)。→ 承重透镜 / pin / promote。
- **Case 2 ·「删除的爆炸半径」(引用图)**:treemap 里最大块最诱人删,但后面 3 轮引用了它。→ **影响感知的删除**;引用图(埋着的宝藏)的天然落点。
- **Case 3 ·「压缩后失忆 / rehydrate」—— ✗ 已否决**:反应式,与预防姿态相悖(见 [principle.md](principle.md) §4)。

## 8. 开放问题 / 待盯

- **工具溯源覆盖率（最该先量）**：第①层（`write→read` 等）能覆盖多少**真依赖**？覆盖率决定"精度骨架"够不够硬、第②③层要补多少——这是整个引用图够不够撑 blast-radius 的关键。
- **验证无金标**：没有"turn 12 真依赖 turn 3"的 ground truth → 倾向**行为式验证**（用户研究：看 blast-radius 是否减少误删/误折），内在 precision/recall 用小 gold 集辅证。
- **引用图方向性**：第①层工具动词（write=源/read=汇）能定向文件类；纯标识符/决策类靠时间启发式（"首提 ≠ 定义"）或第③层 LLM。
- **引用图粒度**：弧 turn-level（配 band、配 `token_turns`）vs invalidate 想要 chunk-level → 需保留 message 级 salient（现 `regime.py:321` union 到 turn 丢了）。
- **弧叠加规模**：arc diagram 过 ~数十轮也会乱 → 按需（选中才渲染）/ bundle / 分量级聚合。
- **压缩自噬地基**：boilerplate 隐形 + 真压缩删历史 → 图的输入被先删 → 须**压缩前快照图并持久化**（复用 v1 着色注册表那套）。

- **证伪剃刀**:主动找第三类不可约信息(既非未来意图、也非外部真相)——找到则改写论点(见 principle §3)。
- **轴冲突**:promote 的"竖直=权威" vs turn 带"竖直=时间"。
- **预览延迟**:本地结构预览够不够"探索感"。
- **画布规模**:自动布局 + 簇粒度,防毛球。
- **必要性频率**:add / steered-fold / invalidate / promote 各自在真实使用里**多频繁**——决定哪些值得做 UI(低频=好东西但非承重)。
