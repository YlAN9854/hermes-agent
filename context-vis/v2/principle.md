## 0. 一句话

v1 把 context 做成了可读可治理的白盒,但**治理动作沿用了既有可视化(treemap 等),没有视图/交互创新**,且更根本的——**没回答"用户手动编辑到底比默认压缩好在哪"**。v2 先回答这个"为什么",再据此设计"怎么做"。

---

## 1. 瓶颈诊断:为什么 v1 的视图是"借来的"

不是巧合,是被**自己的设计公理逼出来的**。

[../../CLAUDE.md](../../CLAUDE.md) 不变量 #3:"**量级编码 token,比例关系神圣不可破**"。一旦"token 大小"是**唯一**神圣的视觉变量,所有视图都必然坍缩成"**面积/长度 = 大小**"——treemap、类型带、sparkline 全是同一件事的皮肤。**视觉自由度被"大小"垄断了。**

而真正的治理问题,**没有一个是关于"大小"的**:
- 哪块**承重**(load-bearing)?——常与大小**反相关**(一句"必须兼容 Py3.8"占 20 token 却定生死)。
- 哪块**还成立**(still true)?——大小不变,可能早被作废。
- 哪块**牵连谁**(引用关系)?——删了谁会悬空?
- agent **此刻在用**哪块?

> **v2 的视觉命题:不背叛"大小是一条真相",但打破它的垄断——引入与大小正交的编码(关联 / 新鲜度 / 承重 / 命运),让布局不再只为"大"服务。**(v2 因此重访不变量 #3:从"唯一"降为"之一"。)
>
> **这条正交维度的首个落地 = 引用图**(v1 检测器 `linking`/`token_turns` 已算、被扔掉的宝藏):它就是**位置式压缩在盲目近似的那个真实结构**,可视化它 = 把支柱一变可见。第一形态 = turn 带上的**弧叠加**;杀手级动作 = drop/invalidate 的 **blast-radius 预览**(impact-aware editing)。详见 [operations.md](operations.md) §6。
>
> **但务必 scoped**:引用图只是**结构/依赖半边**(Case 2 / invalidate / fold / keep 入度)的地基;**Case 1 / promote(被埋的散文约束)走另一条腿**——单次提及的规范性散文,共现图结构上抓不到,靠"高 IDF 浮稀有重要词 + deontic 语言"(见 [operations.md](operations.md) §5/§6)。构建本身用**分层可信度阶梯**(工具溯源=铁证 / 文字-语义=常开线索 / LLM=按需裁判),不靠单一启发式。

## 2. 剃刀:人工介入何时真的赢过默认压缩(论文核心论点)

**诚实前提**:默认压缩(位置式 + 焦点摘要)在"森林态 / 位置≈语义"时本就正确——这正是 v1 检测器在说的(森林态 ContextVis 闭嘴)。所以手动编辑**大多数时候不赢,甚至更差**(又慢又错地替压缩器干活)。

> **剃刀:人工介入的价值,严格等于"用户知道、而压缩器在**决策那一刻**结构上拿不到"的那部分信息。**

压缩器手里只有**过去的 token + 模型**。人能有的、在这之外的,穷举只落三处方位:

| 类 | 是什么 | 模态强度 | 例 |
|---|---|---|---|
| **① 未来意图** | 还没发生/还没说(下一步要 pivot、要弃某支线) | **不可约**(再多训练也没用,信息根本不在) | "我马上转去做 auth" |
| **② 外部真相** | context 之外的世界(外部事实、对错、什么变了、什么是规则) | **不可约**(决策时原则上不可达) | "这文件我带外改过了,现在是假的" |
| **③ 用户内部** | 偏好 / 风险容忍度 / 对自己意图的把握度 / 品味 | **条件不可约**(见下) | "拿不准时偏保守留"、"我要逐字不要散文" |

**第三类的细致结论(与用户共同敲定,别简化)**:它不是"可摊销的 transient 垃圾"。理由:
1. **能力依赖**——不能假设所有 agent 都有 memory-总结能力。
2. **保真缺口**——即便有,从用户 action 总结出的 ≠ 用户**自己认可**的;**用户才是自己 endorsed 偏好的 ground truth**。

→ Hermes 自带 memory,给了一个**可判定的验证闸**:
> **要补的偏好,先查 memory:不在(或不符)→ 编辑 context 就有必要**(这次编辑还能反向修 memory)。

第三类的**结构特征**(把它和前两类分开):前两类往 context 里**喂内容**(一条事实/一个计划);第三类**不喂内容,而是调治理姿态**(设参数)——风险容忍度→fold/keep 默认阈值;表征偏好→摇杆半径默认值;意图把握度→hedge 程度。

**剃刀的推论(=v2 做减法的依据)**:逐块 fold/drop 微操**落在低价值侧**(在重做位置式已做对的事)。价值集中在**注入 ①②③ 的少数高杠杆动作**上 → v2 应**缩小手动面**,只留这些。

## 3. 论文骨架

- **主论点(支柱一)**:position-based auto-compaction 在长程任务里系统性背叛语义;我们**刻画了人工介入的价值边界**——仅当注入决策时机器不可达的信息(不可约两类 + 条件不可约一类,后者带 memory 判定闸),并据此给出**一组实例化操作 + 新交互**。
- **(支柱二,候选)**:把白盒延伸到 agent **最黑的盒子——system prompt**(见 [operations.md](operations.md) §promote)。
- **(支柱一的视觉证明 + 贡献候选)**:**引用图弧叠加 + 影响感知编辑(impact-aware editing)**——破坏性操作(drop/invalidate)提交前显示传递爆炸半径,把不变量 #6(干预透明)**量化**(见 [operations.md](operations.md) §6)。
- **(评估方法,候选)**:**效率 = 用户动作数 / 注入的不可约比特数**;对照"纯 transcript 手编 vs ContextVis",量机器可知杂活(翻找/排序/定位/缝合)的减少——把"减负"从 UX 升格成可测贡献(见 [operations.md](operations.md) §5)。
- **被压测过的边界(加分项)**:我们**试图推翻剃刀**,去找第三类不可约信息——没找到;挖到的"用户内部"是**条件不可约**(memory 闸),"知道在哪出手"则**会约**成"外部真相 × 放置"(见 operations §放置轴)。**证伪不掉的边界才值得写。**
- **声明:此措辞是工作假设,探索中会偏移。** 偏移触发器 = 若冒出**第三类不可约**信息(既非未来意图、也非外部真相)。盯住它。

---

## 4. 姿态:预防式,不是亡羊补牢

ContextVis 是**预防式**(在阈值前/正触发时由用户塑形),不是事后补救。**已否决**"压缩后捞回丢失内容(rehydrate / event horizon)"方向——它是反应式,与预防姿态相悖(决策痕迹)。
